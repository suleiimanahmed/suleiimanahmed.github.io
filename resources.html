Notes 6

  1. Configure Git with git config, initialise a repository with git init and check its state with git status.
  2. Clone with git clone, stage files with git add ., and create and switch to a branch in one step with git checkout -b NAME.
  3. Switch between branches with git switch, push with git push <repo> <branch> and update the local repository with git pull.
  4. Ask coworkers before opening a pull request and merging your branch into main. View change history with git show.
  5. Delete a branch locally with git branch -d NAME and remotely with git push --delete origin NAME.
  6. Resolving merge conflicts is important: git merge NAME (add --abort to cancel), then accept the current, the incoming or both changes.

Notes 6

  1. The overall PyTorch workflow: define a network class, its parameters and the forward function. Put self. before a parameter, otherwise it is not added to the parameter list.
  2. The training metric (loss) must be differentiable. The evaluation metric need not be, and scikit-learn already provides many, so there is no need to write them by hand.
  3. Precision = tp / (tp + fp). Recall = tp / (tp + fn). F1 = 2 × precision × recall / (precision + recall). All range from 0 (worst) to 1 (best).
  4. TensorboardX tracks the torch training process. sklearn.manifold reduces dimensions, and its t-SNE visualises high-dimensional data.
  5. nn.ModuleList has more freedom than nn.Sequential and supports append.
  6. Spatiotemporal GNN deals with a static structure whose features vary in time. A spatiotemporal graph captures the temporal patterns and spatial information of things’ usage events: nodes are locations, timestamps and things, and edges are relationships based on similarities and periodic patterns. The features change along time, while nodes and edges stay connected.

Model predictive control: implementation and a short introduction.

Links 3

  • VideoModel predictive control implementation
  • VideoModel predictive control short introSteven L. Brunton

Notes 3

  1. Basic concept: the strategy u at time k is the optimal short-horizon control starting at k. It is applied to the system, which sends its updated states back to the MPC for time step k+1.
  2. Strength: it can include constraints and work with nonlinear systems (linearised if needed). Weakness: it runs online and is computationally expensive, because the future horizon is rescheduled at every step on receiving feedback.
  3. A compromise is linear parameter-varying control. With faster computing, handling the nonlinear system directly is becoming feasible.
